# ScriptToVideo M6.16 — Breaking Rename

M6.16 introduces the ScriptToVideo application and replaces the Transcript Studio data contract without migration or dual-format support.

## Current files
- Source ASR data: `<stem>.json`
- Edited source subtitle: `<stem>.script.json` with `script_to_video.format = "script-to-video"` and `schemaVersion = 2`
- Project: `<stem>/<stem>.project.json` with `format = "script-to-video-project"` and `schemaVersion = 2`
- Settings: `scripttovideo.settings.json` with `format = "scripttovideo-settings"`
- Published desktop executable: `ScriptToVideo.exe`

All earlier subtitle, project, and settings formats are unsupported. There is no automatic or manual migration and no deletion of older files. Users who need old data must handle it independently.

Natural paragraphs are represented only by word-local `segments[].words[].breakParagraph: true`. Source word timing and order are preserved. Semantic paragraph decisions are made by the `script-to-video-paragraphs` Skill, while pagination remains a separate layout operation.

## Build and verify (Windows PowerShell)
```powershell
npm.cmd ci
npm.cmd run verify
dotnet publish desktop/ScriptToVideo.csproj -c Release -o dist/wpf
.\\dist\\wpf\\ScriptToVideo.exe
```

Windows manual acceptance remains required for tray, window activation, imports, project saves, preview stability, and cancellation/export workflows.
