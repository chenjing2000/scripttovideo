# ScriptToVideo M6.17 — Priority Media Decode Fallback

## Supported files
Import `<stem>.script.json` and look for companion files in the same directory (case-insensitive exact filename, non-recursive):
`.mp4` → `.mkv` → `.m4a` → `.mp3` → `.wav`. No other media extensions are supported.

## Import behavior
- Build an ordered candidate list; skip absent files and decode failures.
- Probe with detached muted WebView2 video/audio elements; video requires initial decoded frame data, audio requires silent playback progress.
- Stop at the first initially decodable file. Later playback failures are reported without automatic switching.
- Keep the prior loaded media and unsaved project intact until the new pair is committed.
- Candidate-specific media tokens never replace the active media token while probing. Stale/cancelled requests cannot commit.
- A mismatched existing project remains protected from overwrite (not rewritten or migrated).
- No transcode, no format/schema change to subtitle/project JSON.
- CLI explicitly accepts the same five formats; CLI `--media` does not perform fallback.

## Acceptance
Run `npm ci && npm run verify`, then Windows `dotnet publish desktop/ScriptToVideo.csproj -c Release -o dist/wpf`. Manually check supported files and malformed codecs in WebView2, silent fallback, unsaved-project preservation, cancel/reimport races, MKV/M4A media compatibility, and MP4 rendering. Windows manual acceptance was completed by the user on 2026-11-15; all scenarios listed below passed.

## Verified Windows manual scenarios (2026-11-15)

- Invalid MP4 falls back to playable MKV.
- Failed MP4 and MKV fall back to playable M4A.
- Failed M4A and MP3 fall back to playable WAV.
- With no decodable candidates, the previous project and preview remain unchanged.
- Cancelling an import or starting another JSON import does not incorrectly switch media.
- M4A and MKV playback, timeline seeking, and MP4 video export work as expected.

These results are based on the user's Windows desktop acceptance run; automated CI additionally checks shared contracts, ordered fallback behavior, and Windows publishing.
